## 二、模板要求 → 系统落地映射

### 1. 三板块 × 六行结构

| 模板要求 | 实现 | 验证 |
|---|---|---|
| 一、抖音整体 | shop_id 跨店聚合（NULL） | 函数内 `agg` 第一段 UNION 跨店 |
| 二、抖音弹动官方旗舰店 | shop_id=1 | meta.shop 表 shop_id=1 |
| 三、抖音弹动个人护理旗舰店 | shop_id=2 | meta.shop 表 shop_id=2 |
| 每板块 6 行（整体/自营直播/自营商品/达人直播/达人短视频/橱窗） | `template` CTE 固定 18 行（3×6） | ORDER BY section_seq,row_seq |

### 2. 指标口径

| 模板指标 | 模型识别口径 | 系统实现 | 验证 |
|---|---|---|---|
| 成交金额 | 模板未注明 | `SUM(user_pay_amount)`（与退款率分母自洽） | OK |
| 成交退款金额 | 成交退款金额（支付时间） | `SUM(refund_amount_pay_time)` | OK |
| 结算金额 | 模板未注明 | `SUM(settlement_amount)` | OK |
| 退款率 | 公式：退款金额/成交金额 | `SUM(refund_amount_pay_time)/NULLIF(SUM(user_pay_amount),0)`（与 V1.0.1.1 一致） | OK |
| 投放消耗 | 投放消耗（店铺被投） | `SUM(ad_spend_shop_promoted)` | OK |
| 投放费比 | 投放费比（剔除退款、店铺绑定） | `SUM(ad_spend_shop_bound)/NULLIF(SUM(settlement_amount),0)`（与 metric_rule_id=197 一致） | OK |

### 3. 经营类型归并（sale_scope × carrier_type）

| 模板口径 | 系统过滤 | 数据验证（shop1 2026-06-01） |
|---|---|---|
| 自营直播 = 自营直播 | `sale_scope='自营' AND carrier_type='直播'` | 163,757.25（独立 SQL 同值） |
| 自营商品 = 自营短视频+商品卡+其他+图文 | `sale_scope='自营' AND carrier_type IN ('短视频','商品卡','其他','图文')` | 143,789.81（独立 SQL 同值） |
| 达人直播 = 合作成交直播 | `sale_scope='合作' AND carrier_type='直播'` | 197.90 |
| 达人短视频 = 合作成交短视频+图文 | `sale_scope='合作' AND carrier_type IN ('短视频','图文')` | 13,721.73 |
| 橱窗 = 合作成交商品卡+其他 | `sale_scope='合作' AND carrier_type IN ('商品卡','其他')` | 1,836.80 |

### 4. 防重口径（关键）

`ad_period='不限'` 是平台汇总行 = 全域+乘方 + 标准+品牌 + 非投放 三时段之和。已验证（shop1 2026-06-01 全部/全部）：`sum(其他时段 user_pay) = 不限行 user_pay = 323,303.49`，差 = 0.00。函数过滤仅取 `ad_period='不限'`，避免重复累加。

## 九、已知约束 / 后续可扩展

1. **店铺名称映射**：模板要求"抖音弹动官方旗舰店"，meta.shop 存"弹动官方旗舰店"。本次报表层独立处理，未改 meta.shop（保护全系统一致性）。如未来需统一，由 meta.shop 改为完整名 + 中文可读层同步即可。
2. **HTML 数据 JSON 体积**：当前 30 天 × 18 行 ≈ 540 行约 200KB。半年内可保持 <2MB。超大量历史时可改为分段加载或直接后端 API。
3. **周报区间**：前端允许任意起止日，未限制必须 7 天——更灵活但需用户自行选择窗口。
