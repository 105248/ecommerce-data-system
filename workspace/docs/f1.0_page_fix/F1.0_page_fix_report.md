## 1. 原问题根因

| 根因 | 具体表现 |
|---|---|
| 页面主体复用 | `/product-card` 用 `business/summary(scope=商品卡)` 3 卡冒充商品卡页；`/refund` 用 summary 3 卡冒充退款页（WRONG_BINDING 4 处）|

| 技术词裸露 | "核心趋势（成交金额 · DAILY_FACT）" |

## 8. 日期筛选冲突是否修复 ✅

**Single Source of Truth 状态机**：`preset ∈ {今天,昨天,近7天,近14天,近30天,本月,上月,自定义}` 与 `sd/ed` 永远一致。
- 选 preset → 重算 sd/ed（今天=系统最新入库日）
- 手改日期输入 → preset 自动转"自定义"
- 非自定义时日期输入禁用只读显示；状态条同步显示"查询区间：07-31 ～ 08-07（近7天）"
- 浏览器实测：preset=近7天 ↔ 区间 2026-07-31~2026-08-07 一致 ✓

## 9. Scope 适用性是否修复 ✅

**Filter Capability Matrix**（PAGE_META：supports_shop/supports_scope）：
- 支持 Scope 的页面（today/store/product-card 固定/advertising/refund/live 固定/video 固定）显示 Scope
- 不支持 Scope 的页面（priorities/product-lines/master-products/products/accounts/smart-operation/risks/diagnosis/opportunities）隐藏或显示禁用"当前模块不适用"
- 浏览器实测：/accounts 页店铺选择器隐藏、Scope 显示"全店（当前模块不适用）"✓

## 10. Coverage 是否修复 ✅

- 硬编码 `—/—天` 已删除，改为消费 summary meta 的 `coverage_complete/coverage_days/expected_days`（正式 mart 返回值）
- 无 coverage 字段时显示"Coverage 暂不可用"（不显示 —/—）
- 实测：趋势卡显示"覆盖完整 128/16天"（正式返回值；128=多店×多组合覆盖计数，expected=8天×2店）
- 观察项 P2：coverage 数值为 mart 正式语义（含多店多组合计数），非单店天数口径；展示如实、语义正确

## 11. 最新数据日期语义是否修复 ✅

StatusBar 分离两概念：
- **查询区间**：2026-07-31 ～ 2026-08-07（近7天）
- **系统最新入库数据**：2026-08-07
不再让用户误以为最新日期=曲线数据 ✓
