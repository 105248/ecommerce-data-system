本阶段架构原则必须锁死：

一、禁止做“万能Function”。
`mart.get_business_period_summary()`只负责高频经营总览Scope：
全店、自营、合作、商品卡、短视频、直播、图文、其他、自营商品卡、合作商品卡、自营短视频、合作短视频以及已确认同类组合。
它的核心参数保持简单：p_shop_name、p_start_date、p_end_date、p_scope_key。
不要往该Function继续加入product_id、account_name、category、terminal、price_band、audience、content等几十个可选参数。

复杂业务域必须使用独立Function：
- mart.get_carrier_period_summary()
- mart.get_account_period_summary()
- mart.get_content_period_summary()
- mart.get_terminal_period_summary()
- mart.get_category_period_summary()
- mart.get_product_period_summary()
- mart.get_price_band_period_summary()
- mart.get_audience_period_summary()

二、时间规则统一：
- p_start_date、p_end_date不能为空。
- p_start_date <= p_end_date。
- p_shop_name='弹动官方旗舰店'查询单店；NULL为未来全部店铺预留。
- Function对外只返回shop_name，不显示shop_id。
- 当前任何代码禁止写死shop_id=1。

三、Scope必须沿用阶段0/0.5/阶段1确认结果：
- 全店 = sale_scope='全部' AND carrier_type='全部' AND ad_period='不限'
- 自营 = 自营 + 全部载体 + 不限
- 合作 = 合作 + 全部载体 + 不限
- 商品卡 = 全部 + 商品卡 + 不限
- 短视频 = 全部 + 短视频 + 不限
- 自营商品卡 = 自营 + 商品卡 + 不限
- 合作商品卡 = 合作 + 商品卡 + 不限
- 自营短视频 = 自营 + 短视频 + 不限
- 合作短视频 = 合作 + 短视频 + 不限
平台已有合法TOTAL时优先直接取TOTAL，禁止用父级+子级重新构造TOTAL。

四、跨期指标必须遵守V1.4：
- 可加金额/人数/订单/件数/曝光/点击等：SUM。
- 非可加ratio/均值：必须按V1.4的分子分母跨期重算。
- 禁止AVG(日退款率)、AVG(日客单价)、AVG(日转化率)、AVG(日费比)。
- 分母为0统一返回NULL。
- 0.1972仍保存/返回0.1972；9.625仍保存/返回9.625，不乘100存储。
- “剔除退款”投放费比/综合费比分母必须继续是settlement_amount，不得回退net_transaction_amount。

五、source_only/缺基础字段：
- 单日可以返回平台源值。
- 多日必须返回NULL，并明确标记不可精确跨期重算。
- 当前6个待平台口径确认和11个缺基础字段禁止SUM、AVG或自行推导。

六、业务域特殊规则：
1. carrier/account不承担全店TOTAL。全店/自营总量必须回deal合法TOTAL。
2. carrier中“全域投放时段/标准+品牌投放”为special_overlap，绝不能与其明细一起SUM。
3. account_name='弹动官方旗舰店'是具体账号，不是TOTAL；“更多账号”是合作剩余聚合桶。
4. content当前真实样本只验证商品卡，不制造短视频/直播内容数据。
5. terminal_type='整体'是合法TOTAL；禁止“整体+明细终端”一起SUM。
6. category必须按category_level隔离父子层级，不同层级绝不能混SUM。
7. product carrier_type='全部'是平台独立TOTAL，禁止用商品卡+图文+直播+短视频明细重建“全部”。
8. price_band 6个价格带已经验证互斥，可以安全SUM重建店铺用户支付金额。
9. audience carrier_type='全部'已验证60/60完全匹配，是合法TOTAL；禁止TOTAL+5个明细一起SUM。
